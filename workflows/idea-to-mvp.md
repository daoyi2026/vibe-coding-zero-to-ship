# Workflow: idea to MVP

Use when a beginner has an idea but does not know where to start.

## Goal

Reach the smallest buildable first version without turning discovery into a product-management course.

## Flow

1. Restate in plain language:
   - who uses it;
   - what they do;
   - what useful result they get.
2. Identify the single core action. Infer it when obvious.
3. Ask only architecture-changing questions that remain unanswered:
   - just the user or other people?
   - must data persist?
   - cross-device?
   - accounts/private user data?
   - uploads?
   - public access?
   - payment?
4. Create a lightweight **NOW / NEXT / LATER** split.
5. Describe the MVP in user-visible behavior, not implementation jargon.
6. Infer P0–P3.
7. If the build is clear, stop interviewing and continue to `new-project.md`.

Do not require personas, TAM/SAM/SOM, a business plan, or a complete roadmap unless the user's actual goal requires them.
